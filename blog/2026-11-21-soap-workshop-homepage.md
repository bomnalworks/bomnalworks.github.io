# 홈페이지 월세 탈출 1편 — 코딩 몰라도 클로드와 대화해서 비누공방 홈페이지 열기

작은 가게나 공방도 "내 이름이 걸린 홈페이지" 하나는 있으면 좋습니다. 그런데 제작을 맡기면 견적이 부담스럽고, 홈페이지 빌더는 매달 사용료가 나갑니다.

이 연재는 **AI 구독은 이미 쓰고 있지만 코딩은 모르는 분**이 추가 비용 없이 홈페이지를 여는 과정을 따라 하기 형식으로 적습니다. 저는 개발자지만 이번에는 일부러 코딩을 하지 않고, 초보처럼 **클로드 채팅과 GitHub 웹 화면만** 썼습니다.

예시는 가상의 "봄날비누공방"입니다. 사진은 가족이 예전에 운영했던 공방에서 찍은 것을 썼습니다.

결과물: [bomnal-lab.github.io](https://bomnal-lab.github.io/)

![완성된 봄날비누공방 홈페이지 첫 화면](/images/2026-11-21/soap-site-hero.jpg)

## 걸린 시간

| 단계 | 한 일 | 걸린 시간 |
|---|---|---|
| 1 | GitHub에 저장소 만들기 | 약 2분 |
| 2 | 클로드와 대화하며 시안 만들기 | 약 1시간 (참고 사이트 비교, 사진 넣기, 수정 포함) |
| 3 | 파일 올려서 공개 | 약 3분 |

첫 시안은 대화를 시작하고 5분 만에 나왔습니다. 나머지 시간은 "더 마음에 들게" 다듬는 데 썼습니다.

## 1. 프롬프트를 몰라도 됩니다

처음에 저는 정보를 빈칸 양식으로 정리해서 붙여 넣는 방식을 준비했습니다. 그런데 직접 해 보니 그렇게 하는 사람은 거의 없습니다. 실제 첫마디는 이랬습니다.

> 비누공방을 하고 있는데.. 수제비누를 만들어.. 아이들 클래스도 하고, 기업 체험 클래스 및 맞춤 선물 주문제작 등을 해.. 나만의 홈페이지를 만들고 싶은데.. 어떻게 하면 될지.. **좋은 예제 프롬프트를 제안해줘. 2개만**

프롬프트를 직접 쓰는 대신 **프롬프트를 만들어 달라고** 한 겁니다. 클로드가 "빠르게 여는 한 장짜리 소개 사이트"와 "예약 기능까지 있는 사이트" 두 가지를 제안했고, "1번으로 해줘" 한마디에 첫 시안이 나왔습니다.

## 2. 디자인은 "유명한 곳 3개 찾아줘"로 정합니다

색이나 글꼴을 말로 설명하기는 어렵습니다. 그래서 이렇게 물었습니다.

> 비누 공방 홈페이지들 중 좀 유명한 곳 3개만 서로 다른 스타일로 찾아줘. 그중에 비슷한 느낌과 컬러를 정하는 게 좋을 것 같아.

클로드가 감성 쇼핑몰형, 여백이 많은 잡지형, 원색이 강한 대형 브랜드형 세 곳을 찾아 화면을 캡처해 보여 줬습니다. 눈으로 보고 고르니 결정이 빨랐습니다.

### 함정 1 — "이 느낌으로"라고 하면 남의 특징까지 따라옵니다

참고 사이트 캡처를 주며 "이 느낌으로"라고 했더니, 시안에 그 브랜드만의 상징 요소(화면 옆의 세로 글자, 제품 배치 구도)까지 들어갔습니다. 그대로 쓰면 베꼈다는 소리를 들을 수 있습니다. 이렇게 다시 말했습니다.

> 참고했던 사이트만의 특징은 빼고 색이랑 여백 느낌만 살려줘.

## 3. 사진은 내 사진으로, 올리기 전에 한 번 거르기

"화면의 비누 그림을 내 사진으로 바꾸고, 공방 사진은 넣는 대로 랜덤으로 바뀌었으면 좋겠다"고 하자 그렇게 만들어 줬습니다.

![공방의 하루. 사진을 폴더에 넣으면 순서가 섞여서 돌아갑니다.](/images/2026-11-21/soap-site-gallery.jpg)

사진을 올리기 전에 이것만은 확인했습니다.

- **아이 얼굴이 나온 사진은 뺍니다.** 손이나 작품만 나온 사진은 괜찮습니다.
- **손님의 개인적인 물건은 뺍니다.** 저는 주문 제작품 중에 손님 가족 사진이 들어간 비누가 있어서 뺐습니다.
- **사진 크기는 클로드에게 줄여 달라고 합니다.** 휴대폰 원본은 장당 3~5MB라 사이트가 느려지고, 촬영 위치 정보가 남아 있을 수 있습니다. 클로드가 줄여 준 사진에서는 위치 정보가 지워져 있었습니다.
- 인터넷에서 찾은 사진은 쓰지 않습니다.

### 함정 2 — 기능 하나에 갑자기 어려워집니다

"사진이 랜덤으로 바뀌게"라는 평범한 요청에, 첫 결과물은 **자동 배포 설정과 별도 스크립트**가 필요한 구조로 나왔습니다. 개발자에게는 익숙하지만 초보는 여기서 반드시 막힙니다. 이렇게 말해 두면 됩니다.

> 나는 터미널이나 자동 배포는 못 써. GitHub 웹 화면에서 파일만 올리면 되게 바꿔줘.

이 한 문장은 **처음부터** 말해 두는 게 좋습니다.

### 함정 3 — 시안에는 가짜가 들어 있습니다

시안에는 "예시 후기"와 `[주소]` 같은 자리 표시가 들어 있습니다. 예시 후기를 그대로 공개하면 거짓 후기가 됩니다. 공개 전에 반드시 지우거나 실제 후기로 바꿔야 합니다.

## 4. GitHub에 저장소 만들기

GitHub에 가입한 뒤 오른쪽 위 `+` → "New repository"를 누릅니다.

- 저장소 이름은 **`내아이디.github.io`**로 정확히 씁니다. 그러면 따로 설정하지 않아도 그 주소로 사이트가 열립니다.
- "Add README"를 켜고 만들면, 30초쯤 뒤 그 주소에 README 내용이 벌써 페이지로 보입니다.

![README만 있어도 주소가 열립니다](/images/2026-11-21/readme-site-live.jpg)

### 함정 4 — 공개 범위가 Private으로 바뀌어 있을 수 있습니다

![조직을 소유자로 고르자 공개 범위가 Private으로 바뀐 화면](/images/2026-11-21/repo-private-trap.jpg)

저는 소유자를 조직으로 골랐더니 공개 범위가 저절로 **Private**으로 바뀌었습니다. 무료로는 Private 저장소로 사이트를 열 수 없습니다. "Choose visibility"가 **Public**인지 꼭 확인하세요.

### 함정 5 — GitHub 화면은 영어뿐입니다

| 화면의 단어 | 뜻 |
|---|---|
| Repository | 저장소 (사이트 파일을 넣는 폴더) |
| Visibility / Public | 공개 범위 / 공개 |
| Add file → Upload files | 파일 올리기 |
| Commit changes | 변경 저장(올리기 확정) |

## 5. 파일 올리고 공개하기

1. 클로드가 준 zip 파일을 **오른쪽 클릭 → 압축 풀기**
2. 저장소 화면에서 **Add file → Upload files**
3. 풀린 폴더 안의 `index.html`과 `images` 폴더를 **마우스로 끌어다 놓기**
4. 아래 초록색 **Commit changes**

업로드 화면을 열고 2분 반 만에 `bomnal-lab.github.io`에 공방 홈페이지가 떴습니다. 폴더째 끌어다 놓으면 폴더 구조도 그대로 올라갑니다.

### 함정 6 — 내 아이디가 공개됩니다

올린 기록에 "Add files via upload | 내 아이디"가 남고, 이 저장소는 누구나 볼 수 있습니다. 실명으로 된 아이디라면 홈페이지용 아이디를 정할 때 한 번 생각해 보세요.

## 정리

| 항목 | 결과 |

| 추가 비용 | 0원 (이미 쓰는 AI 구독만) |

| 공개 주소 | `아이디.github.io` |
| 남은 일 | 주소·카카오톡 링크·후기 자리 채우기, 검색 등록, (선택) 내 도메인 연결 |

다음 편에서는 남은 자리 표시를 고치는 방법 두 가지(GitHub 화면에서 직접 고치기, 클로드에게 고친 파일 받기)를 비교하겠습니다. 검색엔진 등록은 [3편](/blog/2026-11-21-search-engine-registration)에 먼저 적어 두었습니다.
