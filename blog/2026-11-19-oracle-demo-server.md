# 사업자 홈페이지 만들기 2편 - 오라클 무료 서버에 데모 사이트 올리기

1편에서 도메인과 정적 홈페이지를 만들었습니다. 이번에는 서버가 필요한 쪽, 즉 일을 맡기려는 분이 직접 눌러 볼 수 있는 데모 사이트를 올렸습니다.

데모에 올린 것은 작은 사업체용으로 만들어 온 업무 시스템 뼈대입니다. Spring Boot와 Vue로 만들었고, 관리자 화면과 고객 화면, 쇼핑몰, 거래처 주문(B2B) 기능이 들어 있습니다. 서버 비용은 0원이 조건이었습니다.

이번에도 클로드와 같이 작업했습니다. 콘솔 화면 조작과 스크립트 작성은 클로드가 하고, 로그인과 인증, 접속 키 보관, 서버에서 명령 실행은 제가 했습니다.

## 오늘 한 일

| 순서 | 한 일 | 걸린 시간 |
|---|---|---|
| 1 | 예전 오라클 계정 찾아 들어가기 | 약 20분 |
| 2 | 남아 있던 서버 지우고 새 서버 만들기 | 약 40분 |
| 3 | 주소 연결, 방화벽 열기 | 약 10분 |
| 4 | 서버 설치 스크립트 실행 | 약 10분 |
| 5 | 첫 배포와 오류 해결 | 약 20분 |
| 6 | 깃허브 자동 배포 준비 | 약 15분 |

## 1. 5년 전 계정이 살아 있었습니다

오라클 클라우드에는 기간 제한 없는 무료 서버가 있습니다. 가입하려다 예전에 눌러 본 기억이 나서 먼저 찾아봤습니다. 계정은 그대로 있었고, 2021년 3월에 만들어 둔 서버도 꺼진 채 남아 있었습니다.

### 막힌 곳 1 - 같은 비밀번호인데 로그인이 안 됩니다

로그인 화면에서 비밀번호가 계속 틀렸다고 나왔습니다. 원인은 비밀번호가 아니라 **ID 도메인**이었습니다. 오래된 계정은 `OracleIdentityCloudService`라는 도메인에 사용자가 들어 있는데, 로그인 화면 기본값은 `Default`였습니다. 도메인을 바꾸니 바로 들어가졌습니다.

예전 계정을 찾을 때 알아 둘 것:

- **홈 리전은 바꿀 수 없습니다.** 저는 서울이었습니다. 다른 지역이 낫다는 이야기를 듣고 새로 가입하려 했지만, 계정을 여러 개 만드는 것은 약관 위반이라 기존 계정을 쓰기로 했습니다.
- 2021년 서버는 운영체제 지원이 끝났고 접속 키도 없어서 디스크까지 지웠습니다.

## 2. ARM 서버는 자리가 없었습니다

무료 서버 중 쓸 만한 것은 ARM 서버입니다. 무료 한도가 2코어·12GB인 것을 콘솔에서 확인했습니다.

![콘솔의 한도 화면. ARM 서버는 메모리 12GB, 코어 2개까지 무료입니다.](/images/2026-11-19/a1-limits.jpg)

### 막힌 곳 2 - Out of capacity

만들기 버튼을 누르자 자리가 없다는 오류가 나왔습니다. 2코어·12GB도, 1코어·6GB도 같았습니다.

![서버 생성 오류. 서울 리전에 ARM 서버 자리가 없다는 내용입니다.](/images/2026-11-19/out-of-capacity.jpg)

한도 문제가 아니라 그 지역 데이터센터에 실제 자리가 없다는 뜻입니다. 서울처럼 사람이 몰리는 곳에서 자주 생깁니다. 선택지는 세 가지였습니다.

| 방법 | 장점 | 단점 |
|---|---|---|
| 새벽·주말에 다시 시도 | 비용 0원 | 언제 될지 모름 |
| 종량제 계정으로 전환 | 자리를 훨씬 쉽게 얻음. 무료 한도 안에서는 계속 0원 | 카드 등록, 실수하면 과금 |
| 작은 무료 서버(AMD, 1GB)로 먼저 시작 | 바로 만들어짐 | 메모리가 빠듯함 |

저는 세 번째를 골랐습니다. 데모는 지금 필요하고, 자리가 나면 옮기면 됩니다.

![서버 목록. 새 서버가 실행 중이고 2021년 서버는 삭제됐습니다.](/images/2026-11-19/instances.jpg)

### 막힌 곳 3 - 접속 키는 그 화면에서만 받을 수 있습니다

서버를 만들 때 콘솔이 SSH 접속 키를 만들어 줍니다. **그 화면을 벗어나면 다시 받을 수 없습니다.** 내려받은 키는 PC의 `.ssh` 폴더에 두고, 백업은 클라우드 드라이브의 잠금 보관함에 한 벌 넣었습니다. 일반 폴더나 메신저, 저장소에는 넣지 않습니다.

## 3. 주소와 방화벽

Cloudflare에서 `demo` 이름으로 서버 주소를 연결했습니다. 1편의 홈페이지처럼 프록시는 끄고 DNS만 씁니다. 인증서는 서버가 직접 받기 때문입니다.

오라클 쪽 방화벽(보안 목록)에는 기본으로 22번(SSH)만 열려 있어서 80, 443을 추가했습니다.

![보안 목록. 80번과 443번이 추가됐습니다.](/images/2026-11-19/ingress-80-443.jpg)

### 막힌 곳 4 - 방화벽이 한 겹 더 있습니다

오라클의 우분투 이미지는 서버 안에도 방화벽(iptables)이 켜져 있고, 여기도 22번만 열려 있습니다. 콘솔에서 포트를 열어도 접속이 안 되는 대표적인 이유입니다. 설치 스크립트에서 80, 443을 열고 재부팅해도 유지되게 저장했습니다.

## 4. 설치는 스크립트 한 번으로

서버에서 손으로 할 일을 줄이려고 설치 스크립트를 만들었습니다. 한 번 실행하면 아래가 끝납니다.

| 단계 | 내용 |
|---|---|
| 스왑 2GB | 메모리 1GB를 보완 |
| JDK 25 | 우분투 기본 저장소에서 바로 설치됨 |
| MariaDB | 메모리를 적게 쓰도록 버퍼를 64MB로 줄임 |
| Caddy | HTTPS 인증서를 알아서 받고 갱신 |
| 서버 방화벽 | 80, 443 열기 |
| 비밀값 | DB 비밀번호와 암호화 키를 서버 안에서 만들어 root만 읽는 파일에 저장 |
| 서비스 등록 | 자바 힙을 320MB로 제한해 systemd로 실행 |

비밀값을 서버 안에서 만드는 데는 이유가 있습니다. PC나 대화창, 저장소 어디에도 남지 않기 때문입니다.

설치가 끝났을 때 메모리는 600MB 정도 남아 있었습니다.

## 5. 첫 배포는 실패했습니다

PC에서 빌드한 jar를 올리고 재시작했더니 서버가 뜨다가 죽기를 반복했습니다.

### 막힌 곳 5 - 테이블 이름 대소문자

로그에는 "10번 마이그레이션이 실패했다"고만 나왔습니다. 원인은 테이블 이름이었습니다.

- 초기 마이그레이션은 테이블을 소문자(`sys_menu`)로 만들었습니다.
- 10번 마이그레이션은 같은 테이블을 대문자(`SYS_MENU`)로 불렀습니다.
- 개발 PC는 윈도우라 MariaDB가 대소문자를 구분하지 않았고, 리눅스 서버는 구분했습니다.

PC에서는 몇 달을 써도 드러나지 않다가 리눅스에 올리는 순간 터지는 종류의 문제입니다. 데모 DB는 비어 있어서 서버를 대소문자 무시(`lower_case_table_names = 1`)로 바꾸고 DB를 새로 만들어 해결했습니다. 이 설정은 DB를 처음 만들기 전에 넣어야 해서 설치 스크립트에도 넣었습니다.

근본 해결은 마이그레이션과 SQL의 테이블 이름을 한 가지로 통일하는 것입니다. 고객사 DB가 이미 대소문자를 구분하는 설정으로 운영 중이면 서버 설정으로 피할 수 없기 때문입니다. 이건 다음 작업으로 남겼습니다.

다시 시작하니 서버가 떴고, 관리자 화면에 들어가자마자 임시 비밀번호를 바꾸라는 화면이 나왔습니다. 첫 관리자 비밀번호는 저장소에 넣지 않고 서버 로그에 한 번만 나오게 만들어 둔 덕분입니다.

## 6. 깃허브에 올리면 자동으로 배포

마지막으로 `main` 브랜치에 올리면 깃허브가 빌드해서 서버에 배포하도록 했습니다.

### 막힌 곳 6 - 깃허브에 서버 열쇠를 맡겨도 되나

자동 배포를 하려면 깃허브에 서버 접속 키를 넣어야 합니다. 평소 쓰는 키를 넣으면, 그 키가 새는 순간 서버 전체가 넘어갑니다. 그래서 키를 하나 더 만들고 할 수 있는 일을 하나로 묶었습니다.

- 배포 전용 계정과 전용 키를 따로 만듭니다.
- 이 키로 접속하면 셸이 열리지 않고 **jar 설치 스크립트 하나만** 실행됩니다.
- 그 스크립트만 관리자 권한으로 실행할 수 있게 허용합니다.
- 배포 뒤 3분 안에 서버가 안 뜨면 실패로 표시하고 로그를 보여 줍니다. 이전 jar는 3개까지 남겨 둡니다.
