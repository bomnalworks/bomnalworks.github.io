# 사업자 홈페이지 만들기 1일차 - 도메인, 문의용 메일 주소, 깃허브 조직까지 11.17달러

개인사업자 이름으로 홈페이지를 하나 만들기로 했습니다. 호스팅에 돈을 쓰지 않는 것이 조건이었고, 첫날 쓴 돈은 도메인 값 11.17달러가 전부입니다.

이 글은 그 하루의 기록입니다. 작업은 클로드와 같이 했습니다. 화면을 같이 보면서 입력할 수 있는 것은 클로드가 넣고, 비밀번호와 카드 번호와 본인 인증은 제가 했습니다.

## 오늘 한 일

| 순서 | 한 일 | 걸린 시간 |
|---|---|---|
| 1 | 무엇을 만들지 정하기 | 약 30분 |
| 2 | Cloudflare 가입, 도메인 검색과 결제 | 약 20분 |
| 3 | 문의용 메일 주소 만들기 | 약 15분 |
| 4 | 깃허브 조직과 저장소 만들기 | 약 5분 |

## 1. 만들기 전에 질문부터 받았습니다

처음 생각은 "홈페이지, 블로그, 쇼핑몰을 도메인 하나에 다 넣자"였습니다. 클로드에게 계획서를 써 달라고 하면서 계획의 허점을 캐물어 달라고 했더니 질문이 일곱 개 돌아왔습니다.

가장 먼저 받은 질문은 "이 사이트에 누가 들어와서 무엇을 하길 바라는가"였습니다. 전부 다 넣겠다는 것은 메뉴로는 가능하지만, 1순위가 없으면 설계 기준이 서지 않는다는 이유였습니다.

정리된 결론은 이렇습니다.

- **홈페이지의 임무는 하나**: 일을 맡기려는 사람이 들어와 무엇을 하는 곳인지 확인하는 것.
- **쇼핑몰은 직접 만들지 않음**: 결제와 주문 정보를 직접 보관하면 책임이 커집니다. 기존 오픈마켓 링크만 겁니다.
- **블로그는 같은 도메인 아래 `/blog`**: 정적 페이지라 추가 비용이 없습니다.
- **서버가 필요한 것만 서브도메인**: 데모처럼 서버가 도는 것은 `demo.` 같은 주소로 따로 뺍니다.

## 2. 도메인은 Cloudflare에서 샀습니다

국내 업체와 비교한 뒤 Cloudflare로 정했습니다. 고른 이유와 감수한 점은 아래와 같습니다.

| 고른 이유 | 감수한 점 |
|---|---|
| 원가로 팔고 갱신 가격이 오르지 않음 | 달러 결제, 세금계산서 없음 |
| 등록자 정보 비공개가 무료 | 전화 지원 없음, 화면이 영문 |
| DNS와 메일 전달을 같은 화면에서 설정 | 네임서버를 다른 곳으로 바꿀 수 없음 |

검색해 보니 원하는 이름의 `.com`이 비어 있었고 1년에 11.17달러였습니다. 갱신 가격도 같은 금액으로 표시됩니다.

![도메인 검색 결과. .com이 11.17달러이고 다른 확장자는 더 비쌉니다.](/images/2026-11-16/domain-search.jpg)

### 막힌 곳 1 - 한글 입력 상태

가입 화면 이메일 칸에 `ㅏㄴㅅ`가 찍혔습니다. 영문 양식 앞에서는 한/영 키부터 확인해야 합니다.

### 막힌 곳 2 - "Agree to all"은 선택 항목까지 체크합니다

가입 화면 아래에 동의 항목이 네 개 있습니다. 세 개는 필수이고 마지막 하나는 선택인데, 선택 항목은 마케팅 목적으로 개인정보를 외부 업체에 넘기는 데 대한 동의입니다.

![Cloudflare 가입 화면. 아래쪽에 필수 3개와 선택 1개 동의 항목이 있습니다.](/images/2026-11-16/cloudflare-signup.jpg)

저는 전체 동의를 눌러 버렸습니다. 가입한 뒤 설정 화면을 찾아봤지만 이 동의를 끄는 메뉴가 없었습니다. 개인정보 요청을 받는 메일 주소로 철회 요청을 따로 보내야 합니다.

**필수 세 개만 하나씩 체크하면 이 수고가 없습니다.**

가입 직후 알림 설정에 들어가 마케팅 메일 네 종류도 껐습니다. 이쪽은 스위치로 바로 꺼집니다.

### 막힌 곳 3 - First name은 이름, Last name은 성

등록자 정보를 넣을 때 성을 First name에 넣었습니다. 한국어로는 성이 먼저라서 생긴 실수입니다. First name이 이름, Last name이 성입니다. 여권의 Given names와 Surname을 떠올리면 헷갈리지 않습니다.

![등록자 정보 입력 화면. 값은 가렸습니다.](/images/2026-11-16/registrant-form.jpg)

같은 화면에서 알아 둘 것이 두 가지 더 있습니다.

- **Organization 칸**: 여기에 상호를 넣으면 그 조직이 도메인의 공식 소유자가 됩니다. 개인 명의로 두려면 비웁니다.
- **영문 주소**: 도로명과 구를 Address에, 층은 Address 2에, 시와 도는 City와 State에 넣습니다. 동 이름은 도로명주소에 들어가지 않으므로 뺍니다.

### 막힌 곳 4 - 결제 화면의 "내 정보 저장" 상자

카드 입력 칸 아래에 "더 빠른 체크아웃을 위해 내 정보 저장"이라는 선택 상자가 있고, 휴대폰 번호가 미리 들어가 있습니다. 그대로 결제하면 결제 대행사의 간편결제 계정이 같이 만들어집니다.

저는 그대로 결제했고, 결제 직후 처음 보는 곳에서 "이메일 확인" 메일이 왔습니다. 도메인 등록과는 상관없는 메일이라 누르지 않아도 됩니다. 원하지 않으면 결제 전에 그 상자의 번호를 지우면 됩니다.

## 3. 문의용 메일 주소를 공짜로 만들었습니다

홈페이지에 개인 메일 주소를 적고 싶지 않았습니다. Cloudflare의 메일 전달 기능을 쓰면 `contact@내도메인`으로 온 메일을 쓰던 메일함으로 넘겨받을 수 있고, 비용은 없습니다.

순서가 정해져 있습니다.

1. 받을 메일 주소를 전달 대상으로 추가합니다.
2. 그 주소로 온 인증 메일의 버튼을 누릅니다.
3. 도메인에 메일 수신용 DNS 레코드를 넣습니다.
4. `contact@` 주소를 만들고 전달 대상으로 연결합니다.

### 막힌 곳 5 - 인증 전에는 규칙을 저장할 수 없습니다

2번을 건너뛰고 4번으로 가면 전달 대상 목록이 비어 있습니다. 인증된 주소가 없다는 안내만 나옵니다. 인증 메일부터 눌러야 합니다.

3번은 쉬웠습니다. 설정 화면에 필요한 레코드가 "Missing"으로 나열돼 있고, 아래의 "Add missing records" 버튼 하나로 전부 들어갑니다.

![메일 수신용 레코드가 Missing으로 표시된 화면.](/images/2026-11-16/mail-dns-missing.jpg)

규칙이 Active가 되면 끝입니다.

![contact@ 주소의 전달 규칙이 Active인 화면. 받는 주소는 가렸습니다.](/images/2026-11-16/mail-rule-active.jpg)

### 막힌 곳 6 - 첫 메일이 스팸함으로 갔습니다

다른 메일 서비스에서 `contact@`로 시험 메일을 보냈습니다. 전달은 됐는데 Gmail 스팸함에 들어가 있었습니다. 전달된 메일은 보낸 주소와 실제로 넘겨준 서버가 달라 보이고, 오늘 만든 도메인이라 신뢰 이력도 없기 때문입니다.

문의 메일이 스팸함에 묻히면 주소를 만든 의미가 없습니다. Gmail에 필터를 하나 만들었습니다.

1. 설정 → 필터 및 차단된 주소 → 새 필터 만들기
2. 받는사람에 `contact@내도메인` 입력

![필터 조건. 받는사람에 contact@ 주소를 넣습니다.](/images/2026-11-16/gmail-filter-condition.png)

3. "절대 스팸으로 신고하지 않음"과 라벨 적용을 체크

![필터 동작. 라벨 적용과 스팸 제외를 체크했습니다.](/images/2026-11-16/gmail-filter-action.png)

필터를 만든 뒤 다시 보낸 메일은 받은편지함으로 들어왔습니다. **문의용 주소를 만들었다면 필터까지가 한 세트입니다.**

덧붙이면, 시험 메일은 전달받는 메일함이 아닌 다른 서비스에서 보내야 합니다. 같은 Gmail 계정에서 보내면 받은편지함에 따로 뜨지 않아 도착하지 않은 것처럼 보일 수 있습니다.

Gmail은 라벨을 이름순으로만 정렬합니다. 새 라벨이 목록 아래에 묻히면 이름 앞에 `0_`처럼 숫자를 붙여 맨 위로 올릴 수 있습니다.

## 4. 깃허브는 새 계정이 아니라 조직으로

사이트는 GitHub Pages에 올릴 계획입니다. 사업자 이름으로 된 주소가 필요했는데, 계정을 새로 만들지 않고 쓰던 계정에서 조직을 만들었습니다.

- 무료 개인 계정은 한 사람당 하나가 원칙입니다.
- 조직은 무료이고, 주소가 `github.com/조직이름`으로 나와 겉으로는 별도 계정과 같습니다.
- 조직 연락처에는 방금 만든 `contact@` 주소를 넣었습니다.

![조직 생성이 끝난 화면.](/images/2026-11-16/github-org-created.jpg)

### 막힌 곳 7 - 커밋에 개인 계정이 남습니다

조직을 만들어도 공개 저장소의 커밋에는 작성자 이름과 이메일이 남습니다. 사이트 저장소 폴더에서만 작성자를 사업자 이름과 `contact@` 주소로 따로 지정했습니다. 깃허브 웹 화면에서 직접 파일을 고치면 로그인한 계정 이름으로 커밋되므로 웹에서는 수정하지 않기로 했습니다.
