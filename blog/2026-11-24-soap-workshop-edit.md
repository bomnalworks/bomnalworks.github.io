# 홈페이지 월세 탈출 2편 - 공개한 홈페이지 고치기, 직접 고칠까 클로드에게 맡길까

[1편](/blog/2026-11-21-soap-workshop-homepage)에서 가상의 "봄날비누공방" 홈페이지를 공개했습니다. 그런데 클로드가 만든 시안에는 `[주소]`, `[00,000]원`, "예시 후기" 같은 **자리 표시**가 남아 있습니다. 이번 편은 이걸 고치는 이야기입니다.

방법은 두 가지입니다.

- **① 직접 고치기**: GitHub 화면에서 연필 아이콘을 눌러 글자를 바꿉니다.
- **② 클로드에게 맡기기**: 만들었던 대화에서 고쳐 달라고 하고, 받은 파일을 다시 올립니다.

이번에도 코딩은 하지 않고 브라우저만 썼습니다. 결과물: [bomnal-lab.github.io](https://bomnal-lab.github.io/)

## 결론부터

| | ① 직접 고치기 | ② 클로드에게 맡기기 |
|---|---|---|
| 고친 양 | 두 번에 걸쳐 5곳 | 한 번에 18항목 + 후기 삭제 + 문장 추가 |
| 걸린 시간 | 한 번에 약 3분 | 약 14분 (대부분 클로드의 질문에 답하는 시간) |
| 이럴 때 | 숫자나 글자 한두 개 | 여러 곳, 줄을 지우거나 문장을 새로 쓸 때 |

**작은 수정은 직접, 큰 수정은 클로드에게.** 다만 두 방법을 섞으면 함정이 하나 생깁니다. 아래 [함정 3](#함정-3-클로드는-github에서-고친-걸-모릅니다)에 적었습니다.

## 1. 고칠 곳부터 셉니다

처음에는 고칠 곳이 네댓 개쯤이라고 생각했습니다. 실제로 세어 보니 **30곳 가까이** 됐습니다. 가격, 인원, 소요 시간, 자주 묻는 질문의 숫자, 주소, 전화번호, 사업자 정보, 카카오톡 버튼 6개, 예시 후기까지요.

눈으로 훑으면 반드시 빠뜨립니다. 브라우저에서 내 홈페이지를 열고 **Ctrl+F로 `[` 와 `예시`를 찾아** 보세요.

## 2. 방법 ① GitHub 화면에서 직접 고치기

1. GitHub 저장소에서 `index.html`을 누르고, 오른쪽 위 **연필 아이콘**을 누릅니다.
2. 편집 화면 안에서 **Ctrl+F**를 누르면 GitHub 자체 찾기 칸이 뜹니다. 고칠 글자(예: `00,000`)를 넣으면 노랗게 표시됩니다.
3. 그 자리의 글자를 바꿉니다. 대괄호 `[ ]`도 같이 지웁니다.
4. 오른쪽 위 초록색 **Commit changes…** → 창이 뜨면 다시 **Commit changes**.

![편집 화면에서 Ctrl+F를 누르면 GitHub 자체 찾기 칸이 뜹니다](/images/2026-11-24/pencil-edit-find.jpg)

연필 아이콘이 안 보이거나 눌러도 고쳐지지 않으면, 대개 GitHub에 로그인이 안 된 상태입니다.

글자를 아직 하나도 안 바꿨으면 Commit changes 버튼이 흐리게 보이고 눌리지 않습니다. 고장 난 게 아닙니다.

### 함정 1 - "Replace All"은 누르지 마세요

찾기 칸 아래에 "Replace All"(모두 바꾸기)이 있습니다. 편해 보이지만, `[2~3]`처럼 같은 글자가 여러 곳에 있으면 의도하지 않은 곳까지 한꺼번에 바뀝니다. **하나씩 보면서** 고치세요.

### 함정 2 - 커밋 창의 두 번째 선택지

![커밋 창. 위쪽 "Commit directly to the main branch"를 그대로 둡니다](/images/2026-11-24/commit-dialog.jpg)

Commit changes를 누르면 이런 창이 뜹니다.

- **커밋 메시지가 영어로 미리 채워져 있습니다.** 창 아래에 "suggested by Copilot"이라고 적혀 있듯이 GitHub의 AI가 바뀐 내용을 보고 써 준 문장입니다. 그대로 둬도 되고, "가격 수정"처럼 한글로 바꿔도 됩니다.
- **"Commit directly to the main branch"를 그대로 두세요.** 아래 "Create a new branch…"를 고르면 홈페이지에 반영되지 않습니다.

커밋하고 **38초** 뒤 홈페이지에 바뀐 가격이 보였습니다. 커밋 직후에는 예전 화면이 그대로 보일 수 있으니, 1분쯤 뒤 **Ctrl+F5**로 새로고침하세요.

## 3. 방법 ② 클로드에게 맡기기

남은 20곳 넘는 자리를 하나씩 찾아 고치기는 힘듭니다. 그래서 1편에서 홈페이지를 만든 **그 대화방**을 다시 열고 이렇게 보냈습니다.

> 홈페이지에 아직 [대괄호]로 남은 곳이 있어. 하나씩 물어봐 줘. 내가 답하면 그걸로 고친 index.html을 줘.

새 대화가 아니라 **만들었던 대화에서 이어서** 말해야 합니다. 클로드가 그 대화에서 만든 파일을 기억하고 있기 때문입니다. 대화 목록에서 제목으로 찾으면 됩니다.

![클로드가 남은 칸을 세고, 번호를 붙여 하나씩 묻습니다](/images/2026-11-24/chat-first-question.jpg)

클로드는 남은 칸을 18개로 세고 "1/18. 공방 주소를 알려주세요"처럼 하나씩 물었습니다. 답하기 쉽게 이렇게 먼저 알려 줬습니다.

- **"빼줘"**: 그 줄을 지웁니다.
- **"그대로"**: 지금 들어 있는 예시 값에서 괄호만 뗍니다.

답 끝에 오타가 섞여도 알아서 빼고 알려 줬습니다. 편하게 답하면 됩니다.

### 실제 정보만 넣습니다

실제 가게라면 주소, 운영 시간, 전화번호를 그대로 넣으면 됩니다. 이번 예시는 가상 공방이라 이렇게 처리했습니다.

- **주소, 전화번호, 대표 이름, 사업자등록번호는 "빼줘".** 지어낸 번호는 다른 사람의 진짜 번호일 수 있습니다.
- **예시 후기 3개는 통째로 지워 달라고 했습니다.** 받은 적 없는 후기를 올리면 거짓 후기가 됩니다. 진짜 후기가 생기면 그때 넣으면 됩니다.
- 맨 아래에 "전자책 실습용 가상 공방입니다" 한 줄을 넣어 달라고 했습니다.

사업자등록번호를 물을 때 클로드가 "온라인으로 판매를 하게 되면 사업자 정보를 표시해야 할 수도 있어요"라고 덧붙였습니다. 홈페이지에서 무언가를 판다면 꼭 확인할 부분입니다. 예약·결제는 연재 뒷부분에서 따로 다룹니다.

### 함정 3 - 클로드는 GitHub에서 고친 걸 모릅니다

![이미 GitHub에서 30,000원으로 고쳤는데, 클로드는 아직 00,000원으로 알고 있습니다](/images/2026-11-24/chat-old-price.jpg)

이번 편에서 가장 중요한 함정입니다. 방법 ①로 가격을 30,000원으로 고쳐 두었는데, 클로드는 "지금은 '1인 00,000원'이 자리만 잡혀 있어요"라고 물었습니다. 이미 고친 인원 칸도 다시 물었습니다.

클로드는 **자기가 마지막에 준 파일**만 압니다. GitHub 화면에서 직접 고친 내용은 모릅니다. 그대로 받은 파일을 올리면 **직접 고친 게 예전 값으로 돌아갑니다.**

이번에는 같은 값으로 다시 답해서 맞췄습니다. 더 확실한 방법은 이겁니다.

1. GitHub에서 `index.html`을 열고 다운로드 버튼(Raw 옆)으로 지금 파일을 받습니다.
2. 그 파일을 클로드 대화에 끌어다 놓고 **"이 파일 기준으로 고쳐 줘"**라고 시작합니다.

**고치는 곳은 한 군데로.** 직접 고친 적이 있다면 클로드에게 맡기기 전에 지금 파일을 먼저 건네주세요.

### 받은 파일

![고친 파일과 "나중에 채울 것" 정리](/images/2026-11-24/chat-result-files.jpg)

18개 답을 마치자 고친 `index.html`이 나왔습니다. 클로드가 무엇을 뺐는지, **아직 비어 있는 곳**(카카오톡 버튼 링크, 인스타그램, 네이버 지도)이 어디인지도 정리해 줬습니다. "사진은 그대로니 `index.html` 하나만 다시 올리면 된다"는 말도 먼저 해 줬습니다.

## 4. 다시 올리기

1. 클로드 대화의 **Index · HTML** 카드를 눌러 파일을 받습니다.
2. GitHub 저장소 첫 화면에서 **Go to file 옆 `+` 버튼 → Upload files**
3. 받은 `index.html`을 끌어다 놓고 **Commit changes**

![1편에서 "Add file"이라고 적은 버튼이 지금은 + 아이콘입니다](/images/2026-11-24/upload-plus-menu.jpg)

1편을 쓸 때는 이 버튼에 "Add file"이라고 적혀 있었는데, 이틀 만에 글자 없는 `+` 아이콘으로 바뀌었습니다. 화면은 자주 바뀌니 버튼 이름이 다르면 비슷한 위치에서 찾아보세요.

업로드하고 **41초** 뒤 홈페이지에 반영됐습니다.

### 함정 4 - 받은 파일 이름이 `index (2).html`일 수 있습니다

다운로드 폴더에 예전에 받은 `index.html`이 있으면, 윈도우가 새 파일 이름을 `index (2).html`로 바꿔서 저장합니다. 이대로 올리면 GitHub에 파일이 하나 더 생길 뿐이고 **홈페이지는 바뀌지 않습니다.**

올리기 전에 이름을 정확히 `index.html`로 바꾸세요. GitHub는 같은 이름 파일을 덮어쓸 때 따로 묻지 않습니다. 이름만 맞으면 조용히 바뀝니다.

## 5. 마지막은 눈으로 끝까지

![오른쪽 회색 상자 "지도 영역"도 자리 표시였습니다](/images/2026-11-24/site-visit-footer.jpg)

### 함정 5 - 대괄호 없는 자리 표시도 있습니다

다 고쳤다고 생각하고 홈페이지를 끝까지 내려 보니, 오시는 길 옆에 **"지도 영역"**이라고만 적힌 회색 상자가 있었습니다. 대괄호가 없어서 Ctrl+F `[`로도 안 잡혔고, 클로드가 센 18개에도 없었습니다.

마지막에는 **내 홈페이지를 처음부터 끝까지 한 번 눈으로** 훑어보세요. 휴대폰으로도 한 번 보면 더 좋습니다.

## 공개 전 체크리스트

- [ ] Ctrl+F로 `[`, `예시`를 찾아 남은 곳이 없는지
- [ ] 받은 적 없는 후기, 지어낸 연락처·사업자 정보가 없는지
- [ ] 직접 고친 적이 있으면, 클로드에게 지금 파일을 먼저 건넸는지
- [ ] 올리는 파일 이름이 정확히 `index.html`인지
- [ ] 커밋 창에서 "main branch"를 그대로 뒀는지
- [ ] 홈페이지를 처음부터 끝까지 눈으로 봤는지

## 정리

| 항목 | 결과 |
|---|---|
| 추가 비용 | 0원 |
| 직접 고치기 | 한 번에 약 3분, 반영 38초 |
| 클로드에게 맡기기 | 18항목 약 14분, 반영 41초 |
| 남은 일 | 카카오톡 버튼 링크, 인스타그램, 네이버 지도("지도 영역" 상자 포함) |

다음 편에서는 남은 연락 버튼을 채웁니다. 카카오톡 버튼에 무엇을 연결할지, 메일·문의 폼 링크는 어떻게 넣는지 적겠습니다.
